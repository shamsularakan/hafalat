**أُعدّ لصالح مشروع DAWAT | دعوات — 18 نوفمبر 2026**

## 1) الملخص التنفيذي
**دعوة مناسبات** منتج **هجين**: خدمة تصميم+إرسال+إدارة دعوات، **مع تطبيق ذاتي حقيقي** (لوحة تحكم لكل داعٍ، داعون إضافيون بلا حدود لكلٍ لوحته، تطبيق مسح مجاني لموظفي العميل). هذا **أقرب منافس لنموذج DAWAT** (أقرب من أمسية التي هي خدمة مُدارة بلا تطبيق ذاتي).

- **الدعوة = صورة أو فيديو مُصمّم جاهز** (ليس محرر HTML تفاعلي حي) يُرسل عبر واتساب/SMS **رسالة مستقلة لكل ضيف** (لا broadcast)، مع أزرار قبول/اعتذار + **بطاقة دخول بالاسم وباركود فريد يتعطل بعد الاستخدام**.
- **الطلب ذاتي عبر معالج دفع** (/payment/): تحقق OTP واتساب (+SMS fallback) → تسعير ديناميكي → معلومات المناسبة → upsell → دفع (Tabby/Apple Pay/مدى/فيزا/ماستركارد/تحويل). بعد الدفع «تظهر المناسبة مباشرة في التطبيق».
- **التسعير لكل مناسبة** (لا اشتراك)، الأسعار **غير معلنة** بالرئيسية وتظهر داخل المعالج بعد الاختيارات. >1000 دعوة → عرض سعر واتساب.
- **البناء:** موقع متعدد الصفحات **HTML ثابت + Vanilla JS/CSS** بلا إطار SPA، **خلفية PHP AJAX** (جلسات خادم، حفظ خطوات، تسعير ديناميكي، OTP)، **Twilio** للواتساب/SMS، **Cloudflare** CDN/أمان، **Tabby** BNPL. تطبيقات فرعية منفصلة (/payment/، /designs/، /blog/، en.html).
- **الخلاصة لـ DAWAT:** يتفوقون في: onboarding بلا كلمة مرور (OTP واتساب)، تجربة مجانية حية لدعوتك على جوالك، تقسيم سعري بأنماط إرسال (خصم 30% بلا RSVP)، upsell حفل الرجال 35%، بطاقة دخول تُرسل فقط عند القبول، باركود أحادي الاستخدام، تطبيق مسح مجاني لموظفي العميل، مشرفون «افتراضيون» عن بُعد، تصميم مخصص مطابق لصورة قاعتك/كوشك، Tabby BNPL، حفظ خطوات الخادم/استئناف. DAWAT يتفوق في: محرر دعوة متحرك حي (HTML/motion/صوت) vs صورتهم/فيديوههم الجاهز، اشتراك SaaS متعدد المستأجرين vs لكل مناسبة، حصص ذرّية/ledger vs «داعون بلا حدود» بلا مفهوم حصة، معمارية حديثة قابلة للتوسع (Next/React/Postgres) vs PHP/HTML ثابت.

## 2) طريقة البناء (Architecture)
### 2.1 النمط العام
**Multi-page static HTML + PHP AJAX backend + sub-apps منفصلة**، خلف Cloudflare. **لا يوجد إطار SPA** (لا React/Vue/Next/Svelte)، لا أدوات بناء ظاهرة (CSS/JS خام مع cache-busting بالاستعلام `styles.css?v=20260717d`). الخادم PHP يرندر أجزاء من DB (قائمة المدن بـ IDs، أنماط أرقام الدول) والباقي تفاعلي بـ fetch.

```
[Cloudflare CDN/WAF/Insights]
        │
        ├── / (الرئيسية)            HTML ثابت + Vanilla JS + Tajawal self-hosted
        ├── /payment/ (معالج الطلب)  HTML + Vanilla JS + Cairo(Google) + flatpickr(jsdelivr)
        │       └── AJAX → PHP: send_otp / verify_otp / save_step / get_pricing_ajax / process_form
        ├── /designs/ (معرض التصاميم) sub-app مستقل: uploads/YYYY/MM/hash + slugs عربية SEO
        ├── /blog/ + /en.html + صفحات SEO عربية (تصميم-دعوة-باركود/ …)
        ├── /admin/ /private/ /aapi/  (محجوبة robots) — لوحة إدارة + API خاص
        ├── inv.php?gqrc=CODE  (صفحة دعوة الضيف)   redirect.php?r=CODE (استجابة/تحويل)
        └── PHP API → Twilio (WhatsApp/SMS) · DB (MySQL غالبًا استدلال) · Tabby/بوابة دفع
[تطبيق دعوة مناسبات: لوحة الداعي + لوحة الداعي الإضافي + تطبيق مسح الباركود (مجاني لموظفي العميل)]
```

### 2.2 ملاحظات معمارية
- **فصل التطبيقات الفرعية**: كلٌ بأصوله وخطه (الرئيسية Tajawal، الدفع Cairo) → استقلال نشر لكن **اتساق هوية أضعف**.
- **الخادم مصدر الحقيقة**: تعليقات الكود صريحة «The server (save_step.php) is authoritative»، «verify_otp.php already [sets session] — no client-side session sync»، «Sync offer UI from the authoritative server response of get_pricing_ajax». أي: الجلسات والخطوات والتسعير/Coupon تُدار خادميًا والواجهة تعكسها (نضج جيد ضد تلاعب العميل/استئناف).
- **معالجة bfcache**: «bfcache restore kills any in-flight pricing fetch, freezing…» → يعيد جلب التسعير عند pageshow (وعي بتفاصيل المتصفح).
- **Cloudflare**: beacon Insights ×2 (أحدهما `spa:2`)، `server_timing cfCacheStatus/cfEdge/cfOrigin` → CDN/كاش/أمان على الحافة.
- **Twilio**: رد التجربة يحوي `invitation.twilioStatus` / `reminder.twilioStatus` → إرسال واتساب/SMS عبر Twilio (مؤكد).
- **استدلال**: DB علائقية (MySQL/Postgres) خلف PHP (IDs مدن، أنماط دول، جلسات، خطوات، coupons، تصاميم uploads). لا دليل مباشر على نوع DB.

## 3) الباك اند (Backend) — خريطةEndpoints مؤكدة
| Endpoint | الوظيفة | ملاحظات |
|---|---|---|
| `payment/send_otp.php` | إرسال OTP واتساب | 6 أرقام، مؤقت إعادة إرسال، عدّاد تنازلي بالزر |
| `payment/verify_otp.php` | تحقق OTP | **يُنشئ جلسة خادم** (مصدر الحقيقة)، لا مزامنة جلسة عميل |

| `payment/save_step.php` | حفظ خطوات المعالج خادميًا | authoritative؛ استئناف/تغيير الرقم يعيد التسعير/coupon |
| `payment/get_pricing_ajax.php` | تسعير ديناميكي + عروض/coupon | يعيد pricing + offers (men/both) + خصم نمط الإرسال؛ يُعاد جلبه عند bfcache/تغيير الرقم |
| `payment/process_form.php` | إرسال الطلب النهائي | form POST (onsubmit=false → JS يتولى) |
| `…/generate_csrf_token.php` | توليد CSRF | يُحمّل قبل إرسال التجربة |
| `…/send_Test_Main_Website_public.php` | تجربة دعوة+تذكير مجانية | GET phone + POST csrf_token → JSON twilioStatus |
| `redirect.php?r=CODE` | تحويل/استجابة دعوة | من `?r=` بالرئيسية |
| `inv.php?gqrc=CODE` | صفحة دعوة الضيف | من `?gqrc=` (guest QR code) — رمز opaque |
| `/admin/ `/private/ `/aapi/` | إدارة/API خاص | Disallow robots |

**أمان باك اند (مؤكد):** CSRF tokens، **Honeypot** (`company_website` مخفي tabindex=-1)، OTP واتساب+SMS، جلسات خادم authoritative، حفظ خطوات خادمي (ضد تلاعب/فقدان)، أنماط تحقق أرقام per-country (خادم+عميل)، باركود أحادي الاستخدام يتعطل بعد المسح، `/aapi//admin//private` محجوبة. **خصوصية:** FAQ «تستخدم أرقام وبيانات ضيوفك فقط لإرسال دعوات مناسبتك ولا تتم مشاركتها» + conditions.html — **لكن لا سياسة PDPL عامة مفصّلة** مثل أمسية (سطح امتثال أضعف).
**دفع (مؤكد):** **Tabby** BNPL (`checkout.tabby.ai/tabby-promo.js`, `TabbyPromo` widget يعرض أقساط بعد إدراج التسعير AJAX). FAQ: Apple Pay/مدى/فيزا/ماستركارد/تحويل. **بوابة البطاقات/Apple Pay غير مسماة صراحةً بالكود المفحوص** (استدلال: مزود سعودي مثل Moyasar/Tap يدعم Apple Pay+مدى+تابي؛ يُحقن غالبًا في تفاصيل الدفع الديناميكية/خطوة لاحقة). Coupon/خصومات مدعومة.
**إرسال:** Twilio واتساب + SMS، رسالة مستقلة/ضيف (لا broadcast)، دولي، تذكير+موقع للمؤكدين، إشعار الداعي فورًا عند قبول/اعتذار، تتبع حالة الإرسال + عدد مرات الفتح.

## 4) الفرونت اند (Frontend)
- **بلا إطار**: Vanilla JS + CSS خام. لا bundler ظاهر؛ cache-busting `?v=YYYYMMDDx`. jQuery غير ظاهر (fetch/IntersectionObserver خام).
- **الخطوط والأداء (نضج عالٍ)**: الرئيسية **Tajawal self-hosted** (woff2+ttf) preload + `font-display:swap` + **metric-compatible fallbacks** بـ `ascent-override:64.3%/descent-override:35.7%/line-gap-override:20%/size-adjust` لـ (Noto Naskh Arabic/Tahoma/Geeza Pro/Arial) → **CLS≈0 عند swap**. هذا نمط متقدم يستحق التعلم.
- **عدم اتساق**: صفحة الدفع تستخدم **Cairo (Google Fonts CDN)** + **flatpickr (jsdelivr CDN)** بدل Tajawal/محلي → هوية/أداء مختلفان بين الرئيسية والمعالج.
- **الحركة**: IntersectionObserver يضيف `.reveal` لعناصر `.animate` (scroll reveal خفيف، بلا GSAP/Lenis). Lazy-load iframes (فيديوهات المشاركات) بـ IntersectionObserver rootMargin/threshold. Header hide/show on scroll. Scroll-to-top بعد 800px. Hash-scroll بتأخير 500ms.
- **Footer مُضمّن JS**: `fetch('/footer.html')` يحقن التذييل، **يزيل `<link stylesheet>`** من الحقن، يحوّل السنة لأرقام هندية `٠١٢٣٤٥٦٧٨٩`؛ `#footer-placeholder{min-height:700px}` لمنع CLS؛ fallback عند الفشل.
- **التحليلات مؤجلة بذكاء**: GA4 `G-F07F2BY46M` + Google Ads `AW-17967860284` + **Microsoft Clarity `lgc3v42gzp`** (heatmaps/recordings) تُحمّل **عند أول تفاعل** (pointerdown/touchstart/keydown/scroll) أو fallback 10ث بعد load → إبقاء main thread حرًا أثناء التحميل. Pingdom RUM (commented، راقبوا شهرًا). Cloudflare Insights beacon.
- **Modals مخصصة** (alert/confirm/country-picker/price-info) بدل native alert؛ أزرار صريحة نعم/إلغاء؛ checkbox «لا تظهر مرة أخرى».
- **RTL**: `lang=ar dir=rtl` عام؛ حقول الهاتف/OTP `dir=ltr inputmode=numeric maxlength=6`؛ قائمة جوال سفلية بأيقونات SVG (خدماتنا/جرب/آراء/الباقات/تواصل) + CTA «ابدأ الآن» بالترويسة.
- **SEO frontend**: title/description غنية، **meta keywords محشوة بمئات الكلمات** (ممارسة قديمة/خطر)، **نسخ A/B commented** لعناوين/أوصاف/كلمات (تجارب تكرارية)، canonical، hreflang ar/x-default (en.html موجود)، OG/Twitter، **JSON-LD Article + FAQPage (كامل الأسئلة) + Organization**، sitemap.xml يحوي صفحات SEO عربية + صور + blog، روابط مخفية commented لنطاقات أخرى (`barcode-invitation.com`) ولوكالة SEO (`qimmahseo.com`)، Pinterest domain_verify.
- **بloat/تجارب نمو commented**: popup خصم countdown (send_discount_code.php)، استبيان زوار، language switcher، hero variants، أيقونة واتساب عائمة، روابط SEO مخفية. → كود متراكم بتجارب كثيرة (صيانة/حجم).

## 5) طريقة عرض التصميم (Design Presentation)
- **معرض مستقل `/designs/`** بأصوله (`/designs/assets/img/logo.png`) و**uploads منظمة بالتاريخ** `/designs/uploads/2026/06/<hash>.jpg|png` (أسماء مُبصمة → رفع CMS/إداري).
- **صفحة SEO لكل تصميم** بـ slug عربي: `/designs/<التصنيف>/<اسم-التصميم>` (مثال: `/designs/زواج/دعوة-زفاف-ذهبي-بيج-فاخرة`) → **programmatic SEO** يلتقط بحث «دعوة زفاف ذهبية…». breadcrumb: التصاميم › دعوات زواج › اسم التصميم.
- **بطاقة التصميم**: صورة (أو فيديو) + شارة «مميّز» + تصنيف (دعوات زواج/ملكة/عقد قران/تخرج) + عنوان وصفي. **فلاتر**: النوع (الكل/صور/فيديو) + المناسبة.
- **صفحة التفاصيل**: صورة كبيرة (قابلة للنقر/تكبير) + تصنيف + H1 + وصف تسويقي (ألوان/إضاءة/ورود… «قابل للتخصيص باسم مناسبتكم، مع باركود وبطاقة دخول…») + ميزتان (باركود/تأكيد حضور) + CTA «اطلب هذا التصميم» → /payment/ + **وسوم keywords** + **«تصاميم مشابهة»** (شبكة related).
- **التصاميم = صور/فيديوهات مُصيّرة جاهزة** (ليست محرر HTML حي ولا معاينة تفاعلية باسمك قبل الدفع). الجاهز **مجاني ضمن الباقة**؛ **المخصص حسب صورة قاعتك/كوشك بتكلفة إضافية** (ترسل الصورة واتساب → يصممون دعوة تحاكي أجواء مكانك) — **مُميّز قوي**.
- **تسليم الدعوة للضيف**: صورة/فيديو عبر واتساب/SMS + أزرار قبول/اعتذار + بطاقة دخول بالاسم والباركود (تُرسل عند القبول بنمط with_entry_card). أي: «عرض التصميم» للضيف = رسالة واتساب بصورة/فيديو + رابط دعوة (inv.php) + بطاقة، **ليس صفحة ويب متحركة**.
- **مقارنة بـ DAWAT**: نحن نبني دعوة HTML متحركة حية (محرر + مشاهد + صوت + QR داخل الصفحة)؛ هم يبيعون تصميمًا مُصيّرًا (صورة/فيديو) يُرسل كوسائط. فرصتنا: محرر حي + تصدير صورة/فيديو للواتساب (نجمع النموذجين).

## 6) UI / UX
### 6.1 رحلة الطلب (معالج /payment/)
1. **هوية بلا كلمة مرور**: دولة (قائمة بأنماط تحقق per-country) + جوال → «تحقق» → **OTP واتساب 6 أرقام** (مؤقت/عدّاد) → «تأكيد»؛ **SMS fallback بعد 30ث** للسعودية؛ «تغيير الرقم» بـ confirm مخصص. الرقم = الداعي الرئيسي؛ يمكن إضافة داعين إضافيين (كلٍ لوحته).
2. **تسعير ديناميكي (progressive disclosure)**: عدد الدعوات (50–1000 بخطوات 10) + نوع (صورة/فيديو) + الحفل لمن (نساء/رجال/الجميع) + إشراف البوابة (نعم/لا → جنس المشرف/عدد 1–4؛ النسائية بـ 8 مدن). **السعر مخفي حتى اكتمال الاختيارات** («السعر وتفاصيل الدفع تظهر بعد…») → `get_pricing_ajax` يملأ `#dynamic-payment-details` (مصدر حقيقة واحد) + **retry عند فشل الشبكة** + coupon.
3. **متابعة → معلومات المناسبة** (مخفية حتى المتابعة): اسم، نوع (زواج/ملكة/تخرج/عشاء/أخرى)، **طريقة الإرسال 4 أنماط**: (أ) دعوة+أزرار+بطاقة تُرسل عند القبول، (ب) دعوة+أزرار بلا بطاقة، (ج) دعوة فقط بلا أزرار **خصم 30%**، (د) بطاقة دخول فقط. مدينة (بحث بقائمة DB بـ IDs + «لا توجد نتائج→واتساب») + تاريخ (flatpickr).
4. **Upsell / order-bump**: «أضيفي حفل الرجال بخصم 35%» بطاقة مميزة + **تعليم مهم**: broadcast واتساب لا يصل إلا لمن حفظ رقمك → نحن نرسل رسالة مستقلة للجميع. حقول الحفل الرجالي (اسم/تاريخ/عدد/رقم داعٍ آخر بلا OTP). + **ملخص إجمالي مضغوط فوق CTA الدفع** (سطر توفير أخضر).
5. **دفع**: Tabby (أقساط promo widget) + Apple Pay/مدى/فيزا/ماستركارد/تحويل → «إتمام الطلب والدفع» → المناسبة تظهر بالتطبيق فورًا.
### 6.2 أنماط UX مميزة
- **تجربة مجانية حية بالرئيسية**: أدخل جوالك → تصلك **دعوة+تذكير فعليًا الآن** (Twilio) = preview/إثبات وصول قبل الشراء (أقوى من أي demo static). CSRF+honeypot+تحقق رقم per-country+modals نجاح/خطأ واضحة.
- **حفظ خطوات خادمي + استئناف** (save_step authoritative) ومعالجة bfcache/تغيير الرقم (إعادة تسعير/coupon) → لا فقدان تقدم.
- **Progressive disclosure** يقلل الحمل المعرفي (سعر ثم معلومات ثم upsell) لكنه **يخفي السعر** (احتكاك/ثقة).
- **حالات خطأ/إعادة محاولة** صريحة (pricing retry، OTP error/timer، phone error، city no-results→واتساب).
- **إتاحة**: aria-label/role=note، dir=ltr للأرقام، inputmode numeric، maxlength OTP، modals بأزرار صريحة، focus/error borders بلون الهوية `#5e3549`.
- **جوال**: قائمة سفلية ثابتة + CTA ترويسة + scroll-top؛ حقول كبيرة؛ flatpickr ملائم للمس.
### 6.3 احتكاك/ضعف UX
- أسعار مخفية حتى داخل المعالج (مقارنة: أمسية تعلن 249/799/1999 فورًا).
- معالج طويل متعدد الأقسام قبل الدفع (OTP→تسعير→معلومات→upsell) قد يرفع التسرب؛ يخففونه بحفظ الخطوات.
- عدم اتساق خط/هوية بين الرئيسية (Tajawal/#5e3549 عنابي) والدفع (Cairo).
- لا معاينة حية لدعوتك باسمك/تصميمك قبل الدفع (يعوضونها بالتجربة المجانية على جوالك + معرض تصاميم).
- keyword stuffing + كود commented كثيف (ضجيج/صيانة/خطر SEO).

## 7) التسعير ونموذج العمل

## 12) توصيات لـ DAWAT (مرتبة، قابلة للتنفيذ)
1. **Onboarding OTP واتساب بلا كلمة مرور** (مع SMS fallback) كهوية الداعي — يقلل الاحتكاك كثيرًا بالسعودية؛ أبقِ البريد/المنظمات للخيار المؤسسي. (يكمل نموذج جلساتنا الحالي).
2. **تجربة مجانية حية**: «أدخل جوالك → تصلك دعوة+تذكير الآن» عبر مزود واتساب/SMS — أقوى إثبات وصول/preview قبل الدفع (نحن نملك صفحة الضيف؛ ينقصنا إرسال تجريبي فعلي).
3. **تقسيم سعري بأنماط الإرسال**: (دعوة+RSVP+بطاقة عند القبول) / (دعوة+RSVP بلا بطاقة) / (دعوة فقط بلا أزرار = خصم) / (بطاقة فقط) — يوائم ميزانيات مختلفة ويستغل نموذج حصصنا.
4. **Order-bump upsell**: «أضف حفل الرجال/مناسبة إضافية بنفس الطلب بخصم» + ملخص إجمالي/توفير فوق CTA الدفع (يرفع AOV).
5. **بطاقة الدخول تُرسل فقط عند القبول** + **باركود/QR أحادي الاستخدام يتعطل تلقائيًا** (نحن نملك منع إعادة الدخول؛ اجعله افتراضيًا واضحًا + خيار إعادة دخول).
6. **تطبيق/صفحة مسح مجانية لموظفي العميل** (نحن نملك checkin page) + خيار «مشرف افتراضي عن بُعد» أو شركاء ميدانيون كطبقة خدمة اختيارية.
7. **دفع محلي**: Tabby BNPL + Apple Pay/مدى/فيزا/ماستركارد/تحويل عبر مزود سعودي (Moyasar/Tap…) — يستبدل stub ويرفع التحويل/AOV.
8. **معالج طلب بحفظ خطوات خادمي + استئناف + bfcache + retry تسعير** (نمط save_step/get_pricing authoritative) لتقليل التسرب.
9. **تصدير الدعوة صورة/فيديو للواتساب** بجانب صفحة HTML المتحركة (نجمع نموذج مناسبات ونموذجنا) + **تصميم مخصص مطابق لصورة القاعة/الكوشة** كإضافة مدفوعة (ميزة قوية عندهم).
10. **أداء/خطوط**: تبنَّ metric-compatible fallbacks (ascent/descent/size-adjust) لخط ثمانية عند ترخيصه لمنع CLS؛ حمّل التحليلات عند أول تفاعل؛ وحّد الخط/الهوية عبر كل الصفحات (تجنب خط Cairo/Tajawal منفصل).
11. **ثقة/امتثال**: سياسة PDPL مفصّلة (مدد/حقوق/سدايا/نقل) + رقم موحد/توثيق + شروط/استرجاع معلنة (تفوق على مناسبات، ضاهِ أمسية).
12. **SEO نظيف**: صفحات هبوط لكل نوع مناسبة + معرض تصاميم بصفحات SEO + blog + JSON-LD FAQ/Organization، **بلا keyword stuffing**؛sitemap؛ hreflang ar/en لاحقًا.
13. **نموذج تسعير هجين**: اشتراك SaaS (نحن) + خيار «لكل مناسبة»/managed للمترددين — يلتقط شريحتي مناسبات وأمسية.
