# تقرير المراحل والاعتماد — DAWAT MVP

وفق القسم 17.2 من الوثيقة: بعد كل مرحلة — ما اكتمل، ما لم يكتمل، نتائج الاختبارات، وقرار الانتقال.
**نتيجة الاختبارات الحالية: 54/54 ناجحًا (Vitest) · typecheck نظيف · build إنتاجي ناجح.**

## المرحلة 0 — الاكتشاف والتثبيت ✔
- **اكتمل:** PRD معتمد (الوثيقة 1.0)، سيناريوهات العمل والحصص مترجمة إلى نموذج حالات وصلاحيات منفذ ومختبر.
- **لم يكتمل:** شخصيات وخرائط رحلة مفصلة كوثائق منفصلة (مغطاة ضمنيًا بالوثيقة الأم).
- **الانتقال:** ✔ معتمد.

## المرحلة 1 — UX/UI والنظام البصري ✔ (جزئي)
- **اكتمل:** Design tokens بألوان الوثيقة (Navy/Lime/Ivory/Slate/Orange/Success/Danger)، RTL كامل، 16+ شاشة منفذة (تسويق، أسعار، دخول/تسجيل، لوحة، مناسبات، تفاصيل، ضيوف، مفوّضون، تصميم، إرسال، استقبال، تقارير، طاقم، إعدادات، فوترة، صفحة ضيف)، نماذج حركة 6 presets، تبويب سفلي للجوال، حالات loading/empty/error/success.
- **لم يكتمل:** ملفات Figma قابلة للتحرير؛ خط ثمانية المرخص (بانتظار ملفات صاحب المشروع — البديل خطوط نظام آمنة)؛ فحص تباين WCAG formal على كل الدرجات (الألوان الأساسية مختبرة بصريًا: نص كحلي على ليموني/عاجي).
- **الانتقال:** ✔ مشروط باعتماد الهوية المبدئية وتوفر الخط المرخص لاحقًا.

## المرحلة 2 — الأساس التقني ✔
- **اكتمل:** هيكل مستودع منظم، Auth (scrypt + جلسات httpOnly + تحديد معدل)، Tenancy وعزل، أدوار منظمة/مناسبة/تفويض/بوابات، DB + migrations + seed، CI (GitHub Actions: typecheck/tests/build/migrate)، .env.example بلا أسرار، LICENSE.
- **لم يكتمل:** بيئات staging/prod منشورة (قرار الاستضافة Cloudflare/VPS مفتوح بالوثيقة)، 2FA للمشرفين، تأكيد بريد/هاتف فعلي (مزود خارجي).
- **اختبارات:** AC-01 عزل ✔ (اختباران)، جلسات/انتهاء/تجزئة ✔.
- **الانتقال:** ✔.

## المرحلة 3 — إدارة المناسبات والضيوف ✔
- **اكتمل:** CRUD + معالج 3 خطوات بحفظ تلقائي للمسودة، نسخ مناسبة، حالات وانتقالات مشروطة، سعة/وحدة/سياسات، تاريخ هجري/ميلادي وUTC، فئات ومرافقون، استيراد CSV بمعاينة وأخطاء صفوف وتطهير تكرارات (موجود/داخل الملف)، بحث وفلاتر، تصدير، نقل ملكية ضيف مع حفظ الداعي الأصلي.
- **لم يكتمل:** استيراد XLSX (CSV منفذ)، تعديل جماعي متقدم، طاولة/مقاعد (خارج MVP).
- **اختبارات:** AC-06 ✔ (3 اختبارات).
- **الانتقال:** ✔.

## المرحلة 4 — التفويض والحصص ✔
- **اكتمل:** تعيين مفوّض (ربط تلقائي بحساب موجود أو قبول معلق بالهاتف/البريد)، حصة رقمية وصلاحيات دقيقة وانتهاء، إصدار ذرّي داخل معاملة، سجل ledger كامل، إعادة تخصيص بسبب موثق، إيقاف/تنشيط مع سياسة بقاء الدعوات، مفوّض فرعي من حصة المشرف (بإذن صريح)، لوحة مخصص/مستخدم/متبقي/مؤكد/معتذر/حضور لكل مفوّض، قفل الوحدة بعد أول إصدار.
- **لم يكتمل:** ترحيل محكوم لتبديل الوحدة بعد الإرسال (مرفوض حاليًا برسالة واضحة).
- **اختبارات:** AC-02 ✔ (تزامن على الحافة + وحدة أشخاص + سعة + توزيع)، AC-03 ✔ (سياسَتا الإلغاء + ledger)، AC-11 ✔ (idempotency)، إيقاف/تعديل حصة ذاتية ✔.
- **الانتقال:** ✔ — معيار «منع التجاوز في طلبين متزامنين» محقق.

## المرحلة 5 — القوالب والدعوة ✔ (MVP)
- **اكتمل:** 6 قوالب عامة (ملكي/عصري/تراثي/رومانسي/رسمي/شركات)، محرر نصوص/ألوان/حركة/عداد/QR، رفع صوت بتأكيد حقوق إلزامي + شعار/خلفية، مسودة/نشر بإصدارات، صفحة ضيف متحركة (فتح ظرف/تلاشٍ/انزلاق/تكبير/كشف/قلب)، صوت يبدأ بعد تفاعل «فتح الدعوة» مع تشغيل/كتم/مستوى، عداد تنازلي، QR، تقويم ICS، خرائط، reduced-motion، النشر لا يمس البيانات التشغيلية.
- **لم يكتمل:** Timeline متعدد المشاهد المتقدم، مكتبة الحركات القابلة لإعادة الاستخدام (Expand Card/Fan Cards…)، قص المقطع الصوتي، مكتبة أناشيد مرخصة من المنصة، قوالب شركة خاصة بقفل هوية.
- **اختبارات:** تصميم/إصدارات/حقوق صوت/وسائط ✔ (6 اختبارات)؛ AC-08 منفذ تصميميًا (يلزم تحقق أجهزة حقيقية).
- **الانتقال:** ✔ لـ MVP.

## المرحلة 6 — RSVP والإرسال ✔
- **اكتمل:** روابط غير قابلة للتخمين + QR، صفحة RSVP (موافق/معتذر + مرافقون ضمن الحد + رسالة)، «شوهدت» عند أول فتح، فترة ردود قابلة للإغلاق، قوالب نصوص بمعاملات ومعاينة قبل الإرسال، واتساب يدوي + نسخ رابط مع سجل delivery ومنع تكرار 60 ثانية، إشعارات للمالك عبر اللوحة/التقارير.
- **لم يكتمل:** بريد إلكتروني فعلي (مزود)، واتساب API رسمي، تذكيرات مجدولة (jobs)، إشعارات push/بريد للمالك عند كل رد.
- **اختبارات:** AC-04 ✔ (مرافقون + عدم تعديل دعوة الغير)، AC-07 ✔ (مجهول/ملغى/منتهٍ/فترة مغلقة).
- **الانتقال:** ✔.

## المرحلة 7 — بوابات QR ✔
- **اكتمل:** قارئ كاميرا jsQR (بلا رفع صور)، تحقق صلاحية/سعة/استخدام، منع إعادة الدخول أو السماح به بإعداد صريح، تسجيل أول دخول/إعادة، سجل موظف/بوابة/وقت/نتيجة، إجراء يدوي مبرر مع override موثق، لوحة لحظية (20ث)، تكليف بوابات محدد، idempotency للمسح.
- **لم يكتمل:** وضع الشبكة الضعيفة/offline (قرار مفتوح بالوثيقة — تسوية تعارضات لاحقًا)، اختبار حمل مكثف فعلي.
- **اختبارات:** AC-09 ✔ (مكرر/ملغى/سعة/إعادة)، AC-10 ✔ (بوابة خارج التكليف + مناسبة أخرى).
- **الانتقال:** ✔ مع بقاء offline كبند مفتوح موثق.

## المرحلة 8 — التقارير والإعدادات ✔
- **اكتمل:** لوحة تحليلات (صادر/مؤكد/معتذر/منتظر/داخل/لم يحضر/حضور فعلي/سعة متبقية)، لكل مفوّض/فئة/قناة/بوابة/يوم، مؤشر مطابقة AC-12 ظاهر بالواجهة، تصدير CSV (ملخص/ضيوف/دعوات/دخول)، إعدادات مساحة عمل واحتفاظ، أعضاء مؤسسة، قوالب رسائل، سجل تدقيق 200 عملية بواجهة عربية.
- **لم يكتمل:** تقرير PDF ختامي (CSV منفذ)، تصدير/حذف بيانات ذاتي وفق PDPL (عبر الدعم حاليًا).
- **اختبارات:** AC-05 ✔ (إسناد أصلي + نقل)، AC-12 ✔ (مطابقة مباشرة مع rsvps).
- **الانتقال:** ✔.

## المرحلة 9 — الفوترة والتشغيل ✔ (جزئي)
- **اكتمل:** 4 باقات بحدود مفروضة فعليًا (مناسبات/ضيوف/مفوّضون/تخزين/مقاعد)، ترقية/هبوط، فواتير، checkout خلف واجهة مزود (stub محلي معلن)، webhook بتوقيع، نسخ احتياطي حي + فحص سلامة + استعادة مختبرة، CI.
- **لم يكتمل:** مزود دفع حقيقي معتمد، مراقبة/تنبيهات إنتاجية (5xx/jobs/تكاليف)، نشر staging/prod فعلي، مراجعة PDPL/ضرائب مع مختص، سياسة خصوصية وشروط معتمدة قانونيًا.
- **اختبارات:** حدود الباقات ✔ (5 اختبارات)، AC-15 ✔ (نسخ/استعادة).
- **الانتقال:** ✔ للتجربة المحدودة؛ **الإطلاق العام مشروط** ببنود الأمان/القانون/الدفع أعلاه.
